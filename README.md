# SK_Playground E2E Test Suite

This repository contains an automated E2E testing suite generated by Gemini using Playwright and the Model Context Protocol (MCP).

## 🤖 How this Suite was Created with Gemini

This guide outlines the process Gemini followed to go from a simple URL to this fully compliant, self-healing Playwright test suite.

### 1. Trigger the Workflow
**User Action:** Send the workflow command with your target details.
```bash
/e2e_testing_suite feature_name="<Feature>" base_url="<URL>" git_branch_name="<Branch>"
```
*Example:* `/e2e_testing_suite feature_name="SK_Playground" base_url="http://www.uitestingplayground.com/" git_branch_name="https://github.com/skildunne/SK_playground"`

### 2. Context & Dependency Setup
**Gemini Action:**
*   Analyzes the project structure.
*   Installs necessary dependencies (`playwright`, `typescript`, `@types/node`).
*   Installs required browser binaries (Chromium, Firefox, WebKit).

### 3. Analysis & Planning
**Gemini Action:**
*   **Crawls the Base URL:** Navigates to the provided website to understand the UI and identify valid test scenarios.
*   **Generates Test Plan:** Creates a `TestPlan.md` artifact outlining specific user flows to test (e.g., Dynamic IDs, AJAX loading, Shadow DOM).
*   **Requests Review:** Pauses to get user approval on the proposed plan before writing code.

### 4. Code Generation
**Gemini Action:**
*   **Writes Test Code:** Generates Playwright/TypeScript test files (e.g., `scenarios.spec.ts`) implementing the approved plan.
*   **Best Practices:** Ensures code uses semantic locators (`getByRole`, `getByText`) and robust assertion logic (`expect(page).toHaveURL`).

### 5. Automated Verification
**Gemini Action:**
*   Runs the generated tests locally (`npx playwright test`) to ensure they pass immediately.
*   If errors occur, it creates a fix plan and debugs until green.

### 6. Git & Version Control
**Gemini Action:**
*   Initializes/Checks the git repository.
*   Creates the specified feature branch (`feature/SK_Playground`).
*   Commits the verified test code.

### 7. Self-Healing Integration
**Gemini Action:**
*   **Refactors Tests:** Updates test files to use a custom `healing-fixture`. This allows the tests to recover from locator changes using AI at runtime.
*   **Configures Runner:** Sets up a dedicated runner script (`run_and_heal.ts`) that manages the "Fail -> Heal -> Re-run -> Commit" loop.
*   **Verifies Harness:** Executes the runner to ensure the healing infrastructure is functional.

### 8. CI/CD Pipeline Setup
**Gemini Action:**
*   Generates a GitHub Actions workflow (`.github/workflows/ci.yml`).
*   Configures the pipeline to run tests (Chromium, Firefox, WebKit) on every push or pull request.

### 9. Final Deployment
**Gemini Action:**
*   Configures the remote repository origin.
*   Pushes the complete branch (Tests + Healing Logic + CI Config) to GitHub.
